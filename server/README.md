# Собственный сервер лобби ORION

В архиве сервер подготовлен, но не размещён в интернете. По умолчанию сайт продолжает использовать PeerJS. Смешивать разные настройки транспорта у участников нельзя.

## Запуск

Нужен Node.js 22+ на сервере, доступном всем участникам.

1. Скопировать папку server на сервер и выполнить `npm ci --omit=dev`.
2. Задать `ORIGINS=https://ваш-домен` (точный origin сайта без завершающего слеша). Для нескольких сайтов — через запятую. Не ставить `*`.
3. Запустить `npm start` с `PORT=8080` под менеджером процессов.
4. Настроить HTTPS и reverse proxy `/relay` к порту 8080; пример Caddyfile прилагается. Публичный вход — WSS через TCP 443. Не публиковать незашифрованный ws:// в рабочей среде.
5. В `orion-network-config.js` задать `relayUrl: 'wss://ваш-домен/relay'`. Если сайт на GitHub Pages, можно оставить его там, а relay разместить на отдельном домене; ORIGINS должен содержать origin GitHub Pages. Обновить конфиг у всех игроков.
6. Проверить создание комнаты и подключения из обеих реальных сетей без VPN. Доступность конкретного сервера/домена в РФ нельзя подтвердить из проверочного окружения.

## Что делает сервер

Все сообщения лобби идут по WSS вместо WebRTC/STUN/TURN/PeerJS Cloud. При временном разрыве место сохраняется 60 секунд; клиент использует токен сессии и восстанавливает соединение с задержкой между попытками. Подтверждения и номера команд защищают от повторного выполнения при потере ACK. Сервер назначает отправителя по соединению и не доверяет полю label внутри события.

Комната сайта вмещает 16 участников; конкретные игровые столы имеют собственные меньшие лимиты. Это разные ограничения.

## Ограничения

Сервер пересылает сообщения, но симуляция матча остаётся в браузере хоста. Закрытие/перезагрузка страницы игрового хоста или перезапуск relay не восстанавливают матч из базы данных. Для этого нужен отдельный этап: серверная симуляция и хранение матчей. Вкладка игрового хоста должна оставаться активной: фоновые вкладки могут замедлять таймеры.

Состояние комнат хранится в памяти одного процесса; не запускать несколько экземпляров без общего брокера. Это сервер для небольшого закрытого сообщества. Перед публичным массовым запуском нужны отдельная авторизация, защита входа и нагрузочное тестирование.

## Проверка

`npm test` проверяет соединения реальных локальных WebSocket-клиентов: создание/вход, отправителя, адресацию, переподключение, повторы и ограничение комнат. Клиентская диагностика не содержит IP-адресов, ключей и содержимого игровых пакетов.
